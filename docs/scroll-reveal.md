# Scroll-reveal анимация

## Что это

Анимация появления блоков при скролле (в духе ekft.vercel.app): блоки
всплывают снизу с fade-in, картинки внутри них выезжают из лёгкого зума,
заголовки выползают вверх из-под clip-path-маски. Анимация не одноразовая —
при обратном скролле блоки прячутся и проигрываются заново.

## Где лежит

- `assets/js/scroll-reveal.js` — сам скрипт (vanilla JS, без зависимостей и сборки).
- Подключён в `<helmet>` обеих страниц:
  ```html
  <!-- Ferfikez Redesign.dc.html -->
  <script src="./assets/js/scroll-reveal.js" defer></script>

  <!-- Ferfikez Mobile.dc.html -->
  <script src="./assets/js/scroll-reveal.js" data-rv-profile="mobile" defer></script>
  ```
  dc-рантайм переносит содержимое `<helmet>` в `<head>`, пересоздавая теги
  `<script>` вместе с атрибутами, поэтому скрипт выполняется как обычный
  внешний скрипт страницы и профиль до него доезжает.

## Профили

Вёрстки две и анимируются они по-разному, поэтому параметры вынесены в
`PROFILES` в начале файла. Профиль выбирается атрибутом `data-rv-profile`
на теге `<script>`, по умолчанию — `desktop`.

| | `desktop` | `mobile` |
|---|---|---|
| Контейнеры целей | `main > div`, `section > div`, `footer > div` | `main > section > div`, `main > div`, `main > section`, `footer`, `section > div` |
| Сдвиг | 26px | 20px |
| Длительность | 0.8s | 0.7s |
| Задержка соседей | 70ms, до 5 штук | 60ms, до 4 штук |
| Маска заголовка | 0.95s | 0.9s |
| Порог показа | 92% высоты экрана | 94% |
| Зум картинок | есть (1.06 → 1) | выключен — на узком экране только мылит |

Помечаются **прямые потомки** перечисленных контейнеров, плюс любые `h1`/`h2`
получают маску-разворот. Менять HTML не нужно.

Шапка (`header > div`) намеренно не анимируется ни там, ни там: она sticky.
На мобильной странице так же не трогаются оверлей бургер-меню и нижняя панель
«Hívás / Ajánlat» — оба лежат в корневой обёртке, а не в `main`/`section`/`footer`.

Если появятся новые секции с другой обёрткой — правьте `groups` нужного профиля.

## Свои transform и opacity элемент не теряет

Декоративные иконки-инструменты — прямые потомки `<section>`, то есть тоже
цели анимации, и у них в разметке уже есть `transform:rotate(-14deg)` и
`opacity:0.22`. Поэтому при разметке скрипт запоминает собственные `transform`
и `opacity` элемента (`data-rv-t`, `data-rv-o`), скрытое состояние собирает как
`translateY(...) <свой transform>`, а при показе возвращает ровно исходные
значения. Без этого иконки после появления вставали бы прямо и непрозрачными.

По той же причине картинки со своим `transform` исключены из зума — зумятся
только помеченные `data-rv-zoom`.

## Отличия от исходного handoff-файла

Файл пришёл framework-agnostic заготовкой под десктопную вёрстку; под этот
проект в нём изменено следующее:

1. **Профили** вместо одного набора констант — см. таблицу выше. Мобильные
   значения взяты из версии, которая была вписана прямо в dc-скрипт мобильной
   страницы; теперь обе страницы используют один файл.
2. **Список селекторов** сверен со структурой: у `desktop` убран
   `header + section` (на этой странице после шапки идёт `<main>`, совпадений нет).
3. **Добавлен `MutationObserver`** — страницы рендерятся dc-рантаймом на React
   и перерисовываются при смене раздела, вкладок услуг и фильтров блога.
   Наблюдатель до-размечает новые узлы. Следит только за `childList`, а скрипт
   правит `style` и `data-*`-атрибуты — зацикливания нет.
4. **Дебаунс наблюдателя на `setTimeout`, а тикер вызывает полный `setup`** —
   в фоновой вкладке `requestAnimationFrame` не тикает, и на нём разметка
   терялась: заголовки оставались без маски.
5. **Сохранение собственных `transform`/`opacity`** — см. раздел выше.

Ручной вызов `window.refreshScrollReveal()` тоже остался — на случай, если
контент вставят в обход React.

## Если страницу пересобрали в дизайн-хосте

Экспорт из хоста может принести версию, где анимация снова вписана в
`class Component` (`componentDidMount` / `setupReveal`). В этом случае из
экспортированного файла нужно вырезать этот блок и вернуть тег `<script>` в
`<helmet>` — иначе анимация будет отрабатывать дважды, двумя разными
реализациями.
